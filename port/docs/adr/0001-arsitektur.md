# ADR 0001 — Arsitektur portal, keputusan K-1..K-12, dan risiko versi

Status: diterima (plan 10, 28 Okt 2026). Sumber rancangan: `plans/2026-10-21-portal-SPEC.md`
dan `plans/2026-10-21-portal-KONTRAK.md` di repo DisparDataPlatform.

## Konteks

Disparekraf meminta portal baru di server Kominfo dengan Nuxt (frontend) dan Laravel 10 + Oracle
19c (backend). Data pariwisata ada di lakehouse kita (ClickHouse) yang tidak terjangkau dari server
Kominfo. Portal harus tampil dan berangka sama dengan `dispar.rantai.dev` yang sekarang.

```
Browser → Nuxt SSR (proxy /_api, token tidak pernah ke browser)
        → Laravel 10 /api/v1 (auth, log history, cache + snapshot di Oracle)
        → Data API /v1 (FastAPI, satu-satunya yang menulis SQL ke ClickHouse)
        → ClickHouse lakehouse
```

## Keputusan K-1..K-12

Nilai default SPEC dipakai kecuali disebut lain. Pemilik boleh membatalkan tiap keputusan.

| K | Keputusan | Alasan singkat |

## Keputusan teknis plan 10

- **Kunci Oracle: sequence + trigger bawaan yajra**, bukan `GENERATED BY DEFAULT AS IDENTITY`.
  SPEC §6 menyebut keduanya; yang dipakai satu saja supaya tidak campur. Dump
  (`scripts/oracle-dump.sh`) memuat sequence dan trigger itu.
- **Nama objek Oracle ≤ 30 karakter**: nama index ditulis eksplisit (Laravel membuat nama
  otomatis sampai >50 karakter).
- **Tes backend memakai Oracle XE 18 sungguhan**, bukan sqlite, supaya perilaku yajra/Oracle
  (CLOB, `IS JSON`, ORA-00001, byte semantics) ikut teruji.
- **Fixture Data API = rekaman body mentah** (`tools/fixture-server`), bukan mock dari OpenAPI:
  mock statis tidak bisa melayani filter dan paging. URL yang belum direkam → 599.
- **Tes di skema `portal_test`**, terpisah dari skema dev `portal`, karena `RefreshDatabase`
  menjalankan `migrate:fresh`. Skema dibuat `backend/docker/oracle-startdb` tiap Oracle start.
- **Rantai X-Forwarded-For**: proxy `/_api` meneruskan XFF yang masuk lalu menambahkan IP soket
  (pola XFF standar). Laravel membaca dari kanan dan melewati alamat di `PORTAL_PROXY_TEPERCAYA`,
  jadi IP asli tetap benar selama daftar itu memuat server Nuxt **dan** reverse proxy/LB di
  depannya. Kalau LB tidak didaftarkan, yang tercatat adalah IP LB (bukan IP palsu dari klien).
  Batas tunggu proxy ke Laravel 330 s (di atas timeout ekspor 300 s); lewat itu → 504.
- **Parser angka `parseIdNum` diperbaiki, bukan ditiru** (keputusan pemilik 29 Okt 2026,
  pengecualian K-10). `idNum` di `lib/agg.ts` v2 membaca titik ribuan sebagai desimal
  ("1.000"→1, "1.234.567"→null). Kini: angka JS dikembalikan apa adanya; string berpola
  ribuan Indonesia (`1.234.567`, `1.234,5`) dibaca sebagai ribuan, koma tunggal sebagai
  desimal, selain itu titik desimal (`12.5`). Perbaikan yang sama dibuat di v2 supaya paritas
  pulih setelah v2 di-deploy.
- **Chart: builder opsi murni + satu pembungkus `EChart.vue`.** `utils/chart-options/*` menyalin
  opsi tiap komponen v2 sebagai fungsi `(props, expanded) → option`; komponen Vue hanya memilih
  tinggi dan keadaan kosong. `categoryZoom` menerima lebar layar sebagai argumen (bawaan
  `window.innerWidth`, sama dengan v2) supaya bisa diuji. Snapshot pertama dibandingkan dengan opsi
  komponen v2 asli lewat harness golden plan 01: 28 kasus (normal + diperbesar) identik, termasuk
  keluaran formatter. Di browser, 7 chart `/dashboard/pdrb-ekraf` identik per piksel pada 1440 px
  dan 375 px.
- **`vue-echarts/csp`**, bukan build bawaan: build bawaan menyuntik `<style>` lewat `document` saat
  diimpor sehingga SSR gagal (500). Gaya `x-vue-echarts` ditulis inline di `EChart.vue`.
  Modul ECharts didaftarkan per kebutuhan (bar, line, pie, treemap + grid, tooltip, legend,
  dataZoom, canvas) **plus fitur `LabelLayout` dan `UniversalTransition`** yang ikut di build
  `echarts` lengkap v2 — tanpa `LabelLayout`, `labelLayout.hideOverlap` tidak berjalan dan label
  bertumpuk di modal GroupedLines (ditemukan saat membandingkan dengan produksi). `notMerge` +
  `lazyUpdate` dan ukur ulang otomatis sama dengan echarts-for-react.
- **API Vue untuk dua komponen**: `ModeToggle` memakai `v-model` (bukan `value` + `onChange`);
  `class` pada `ChartCard` digabung Vue ke div akar setelah kelas bawaan (hasil sama dengan v2).
- **Paritas visual terhadap produksi** (dispar.rantai.dev, 29 Okt 2026, `/dashboard/pdrb-ekraf`
  vs galeri `/_kerangka` dengan data golden yang sama): 7/7 chart dan 7/7 modal "Perbesar grafik"
  identik per piksel pada 1440×900 dan 375×812; tinggi header, lebar item nav, KPI, dan kartu sama.
- **Font = berkas yang persis dilayani produksi, bukan fontsource + fontaine** (menyimpang dari
  SPEC §5.1). Plus Jakarta Sans dari `@fontsource-variable` 5.3.0 berbeda versi dari berkas Google
  Fonts yang di-bundle `next/font` saat v2 dibangun: teks yang sama 3,5% lebih sempit (1088 vs
  1128 px), sehingga baris membungkus berbeda dan ambang paritas 2% terlewati. Empat subset woff2
  produksi di-host di `public/fonts/plus-jakarta-sans/` (OFL, `OFL.txt`); aturan `@font-face`,
  termasuk fallback `size-adjust` Arial buatan `next/font`, disalin dari CSS produksi, sehingga
  `@nuxtjs/fontaine` tidak diperlukan lagi. Subset latin dipreload seperti `next/font`.
- **Gradien chart berbentuk objek** `{type:'linear', x, y, x2, y2, colorStops, global}` (SPEC §5.1),
  setara `new graphic.LinearGradient(…)` v2; builder tidak lagi mengimpor `echarts/core`.
- **`xlsx` 0.18.5 (versi v2), bukan 0.20.3.** Uji ekspor contoh v2 dengan kedua versi: `.xlsx`
  identik per byte, `.xls` isi selnya identik tetapi 0.20.3 menambah record gambar kosong
  (MSODRAWINGGROUP/MSODRAWING), jadi berkasnya tidak identik → aturan SPEC §5.1 memilih 0.18.5.
  Risiko: advisori GHSA-4r6h-8v6p-xvw6 (prototype pollution) dan GHSA-5pgg-2g8v-p4x9 (ReDoS) ada
  di jalur *membaca* berkas; portal hanya *menulis* ekspor, dan SheetJS dimuat malas saat klik.
  Catatan bila pemilik memilih 0.20.3: npm di lingkungan kerja menolak paket `remote`
  (`allow-remote`), jadi tarball resmi (`xlsx-0.20.3.tgz`, sha512 `oLDq3jw7…uH+3AJA==`) perlu
  divendor ke repo dan dipasang lewat `file:`.
- **SdiTable memakai rute Laravel dataset** (plan 11): halaman pertama tanpa pencarian lewat
  `dataset/{slug}/halaman`, dengan bentuk yang diandalkan
  `data = {dataset: {total_bronze}, kolom: {items}, baris: {items}}` dan `meta.total` = total baris
  Silver; pencarian dan halaman berikutnya lewat `dataset/{slug}/baris?page&size&q`
  (`page = baris_dimuat / 50 + 1`, setara offset v2). Jawaban usang (slug/pencarian lama) dibuang.
- **Peta = komponen universal, bukan `.client.vue`.** SSR merender teks memuat yang sama dengan
  fallback `ssr:false` v2 ("Memuat peta…", "Memuat peta venue…", "Memuat peta Spatial…"); Leaflet
  (dan markercluster, yang butuh `window.L`) diimpor dinamis di `onMounted`. SPEC §5.1 mengizinkan
  `.client.vue` atau pembungkus client-only.
- **Basemap K-9**: `useBasemap.addBasemap` memasang Esri seperti v2; bila 3 tile alas gagal sebelum
  satu pun termuat, Esri diganti OSM. Ikon marker dari `/leaflet/*` lokal. VenueMap menaruh label
  Esri di pane tile bawaan (meniru TileLayer react-leaflet v2), peta lain di `shadowPane`.
- **SpatialMap hanya tampilan**: props berbentuk `/v1/spasial` (titik ringkas, `cities`,
  `kepadatan_berkoordinat`, `kepadatan_tanpa_koordinat`); popup tampil dari data ringkas lalu
  sertifikat menyusul dari `muatDetail(id)` (`/v1/spasial/titik/{id}`). Pencarian sama dengan v2
  (nama + alamat + wilayah): titik ringkas `/v1/spasial` membawa `address` sejak plan 11 (keputusan
  pemilik 29 Okt 2026; payload ±1,26 MB vs 0,85 MB tanpa alamat).
- **HeroDark** = pola hero gelap yang di v2 ditulis ulang di enam berkas (inventaris A §8);
  padding vertikal per halaman lewat prop `pad`. **PageFooter tidak ada di v2** (SPEC §5.2
  menyebutnya di `components/app`), jadi tidak dibuat.
- **ESLint hanya untuk aturan pemisahan layer** (SPEC §5.3): `import/no-restricted-paths` dengan
  zona per layer fitur + `shared`, resolver TypeScript membaca alias Nuxt (`#layers/*`, `~~/*`).
  Tidak memasang aturan gaya (prettier/recommended) — di luar cakupan plan 10. ESLint 9.39.5
  karena `eslint-plugin-import` 2.32.0 belum mendukung ESLint 10. Mutation check di
  `tests/unit/arsitektur.spec.ts` membuktikan impor relatif, alias, dan `.vue` ditolak.
  **Celah yang diketahui**: komponen/composable auto-import Nuxt dari layer lain tidak memakai
  `import`, jadi tidak tertangkap ESLint; layer fitur (plan 11+) perlu menamai komponennya dengan
  awalan fitur dan review menjaga aturan ini.
- **Galeri `/_kerangka`** (dihapus di plan 17): `index` (komponen + PDRB Ekraf golden),
  `pariwisata` (PariwisataShell + VenueMap), `spasial` (SpatialMap, kepadatan dihitung di galeri
  dari golden), `dashboard` (layout dashboard). RawDataDisclosure/SdiTable memanggil rute dataset
  Laravel plan 11, jadi sampai plan 11 galeri menampilkan keadaan error-nya; e2e mencegat rute itu.
- **CI: satu sumber perintah** di `scripts/ci/*.sh`; `.github/workflows/ci.yml` dan `.gitlab-ci.yml`
  hanya menyiapkan lingkungan. Oracle selalu sebagai *service* CI (bukan compose/dind, karena
  dind GitLab tidak bisa bind-mount direktori build). Service tes memakai `APP_USER=portal_test`
  (skema yang dipaksa phpunit.xml). GitHub membangun image PHP di job (cache buildx); GitLab
  membangunnya sekali ke registry (`image-php`). Cek dump di GitLab memakai image
  `gvenzl/oracle-xe` sebagai klien sqlplus; `oracle-dump.sh` menerima `ORACLE_SQLPLUS` +
  `ORACLE_DSN` untuk itu. Diverifikasi lokal: actionlint 1.7.12 dan `gitlab-ci-local --list`
  (skema valid), serta tiap skrip CI dijalankan di image/service yang sama (Pest 59, migrasi
  naik-turun-naik di XE 21, dump ke skema kosong lewat compose, `docker exec`, dan klien gvenzl).
  CI sungguhan belum pernah jalan (repo belum didorong).
- **E2E plan 10 hanya frontend**: Nuxt hasil build + Playwright (desktop 1440 dan Pixel 7) untuk
  galeri, satu redirect lama, dan 404. Rute dataset Laravel (plan 11) dipalsukan di browser
  sesuai kontrak; tile peta dari internet dijawab 204 supaya tidak bergantung jaringan CI. Tes
  kesehatan backend (`E2E_LARAVEL_URL`) dijalankan lokal; di CI kesehatan dijaga Pest. Plan 11
  menambah backend + fixture-server ke job e2e saat rute fitur pertama ada.
- **`@playwright/test` 1.64.1** (rilis 14 Okt 2026); job GitLab memakai image Playwright versi
  yang sama.

## Keputusan teknis plan 11 (dataset, beranda, docs)

- **Sumber paritas = versi yang tayang**, bukan hanya `6b858eb`. `dispar.rantai.dev` menjalankan
  `dispar-v2:464fc15`; sejak `6b858eb` katalog mendapat filter Sumber + Tag (c3f536f), chart builder
  mendapat pilihan urutan dan `kbli` (a7996d2, 55c45af), dan item asisten AI di nav berganti
  "Jekate" (464fc15). Portal mengikuti versi tayang (K-10); KONTRAK §2.1 memang sudah memuat
  `sumber`/`tag`. Item Jekate/AI dan dock-nya tetap tidak di-port (SPEC §1, §5.4).
- **Kelas P lewat `Shared/Cache/BacaCache`** (body mentah, kunci SHA-256 karena kolom KEY 255 byte,
  TTL `portal.cache_menit` = 15). Error tidak di-cache. Kunci snapshot/cache dibuat
  `Shared/Support/KunciQuery` (parameter kosong dibuang, kunci diurutkan); job sinkron plan 16
  memakai fungsi yang sama dengan `varian` rute (katalog: `tier=semua`, `tier=primer`).
- **`dataset/{slug}/halaman`** = `{dataset, kolom, baris}` disambung sebagai JSON mentah; `meta`
  = meta baris (`total` = baris Silver), `source` gabungan ketiganya; `sumber = cache` hanya bila
  ketiganya dari cache. Detail dipanggil lebih dulu supaya slug tak dikenal langsung 404.
- **Ekspor** = `StreamedResponse` yang menyalin body Data API per 64 KB; `Content-Type`,
  `Content-Disposition`, `X-Row-Count` diteruskan, `X-Accel-Buffering: no`. LOG_HISTORY mencatat
  filter (query) dan jumlah baris dari `X-Row-Count`. Proxy Nuxt ikut meneruskan `X-Row-Count`.
- **Validasi Laravel → 422 `INVALID_PARAM`** (pola plan 10); nilai filter/sort/kolom tetap
  divalidasi Data API (400 diteruskan). Draf OpenAPI menulis 400 untuk keduanya.
- **Halaman detail dimuat di browser** (`onMounted`), sama dengan client component v2: HTML SSR
  berisi "Memuat data dari Satu Data Jakarta…". Katalog dan beranda dimuat SSR (`useAsyncData`),
  tanpa seed statis `lib/sdi-data.json` (E §1.1). Teks 404 v2 ("Dataset belum tersedia di
  lakehouse") ditampilkan untuk 404 apa pun dari Laravel.
- **Komposabel**: `useDataset()` = satu fungsi per endpoint (pola plan 12–15); keadaan tabel detail
  di `useDatasetBaris(slug)`. Filter tidak ditulis ke URL halaman (v2 juga tidak); serialisasi
  filter ↔ query API diuji bolak-balik.
- **`/docs` (P3)**: isi dari ekspor Scramble yang di-commit (`docs/api/laravel-openapi.json`) →
  `scripts/docs-dari-openapi.ts` → `layers/docs/data/endpoints.json`. Ringkasan/deskripsi dari
  docblock controller, keterangan parameter dari komentar aturan FormRequest. CI backend gagal bila
  ekspor berbeda dengan kode; Vitest gagal bila `endpoints.json` berbeda dengan ekspor. Rute
  `sistem/*` tidak ditampilkan. Base URL dari `NUXT_PUBLIC_API_BASE_URL`. Pill "Baca publik tanpa
  autentikasi" diganti "Token layanan (Bearer)" karena API portal memang bertoken (K-5).
- **Uji paritas** (`tests/parity/`, `playwright.parity.config.ts`, lokal): tangkapan produksi
  menjadi pembanding `toMatchSnapshot` (ambang 2%) dan himpunan angka `<main>` harus identik.

  (`samakanBaris`): yang diuji render atas data yang sama. `/docs` dibandingkan hero layar pertama

- **E2E melawan Laravel + fixture-server** (tanpa memalsukan rute di browser). CI:
  `scripts/ci/e2e.sh` menyalakan fixture-server dan Laravel (`laravel-e2e.sh`: skema bersih, akun
  layanan, token ke berkas, `artisan serve`; nilai env ditulis ke `.env` karena `serve` tidak

## Keputusan teknis plan 13 (indikator)

- **Data API diperluas** (lakehouse/data-api, kontrak + tes): detail `/v1/indikator/{code}` kini
  membawa `indikator` (nama, definisi, dimensi, owner, catatan — untuk hero) dan `konteks`
  (benchmark `gci_gpci_benchmark` untuk kartu IndexContext; usulan C §4.4), dan tabel artis
  seni-pertunjukan membawa `tautan` (URL "Verifikasi ↗"). Tanpa itu halaman tidak bisa meniru v2.
- **Halaman indikator generik**: 19 view React dipipihkan Data API menjadi `kpis` + `blocks`
  bertipe; satu `IndikatorDetail` merender semua kode (C: satu komponen per arketipe). Pemetaan
  tipe → komponen dan warna batang setengah lebar (hijau, kuning) diambil dari view v2; MomNote
  (CE2, CE3, CI-FV) konstanta. Prefiks silang diterima.
- **Feature Indikator generik** seperti dashboard; satu percobaan dengan `dataapi.timeout_lambat`
  (60 s) karena pemilihan dataset (K-12) bisa belasan detik saat cache Data API dingin.
- **Perbaikan store cache Oracle**: `put()` memakai update lalu insert, bukan `upsert` (MERGE …
  USING SELECT :bind FROM dual), karena bind > 32 KB gagal dengan ORA-01461 (respons
  seni-pertunjukan ±64 KB).
- **Defect D ditiru**: "Nilai terbaru" bergantung urutan baris ClickHouse tanpa ORDER BY, jadi bisa
  berbeda dengan produksi yang dibekukan ISR (contoh 30 Okt: CI-TA 72,22 vs 291.801). Uji paritas
  mengecualikan angka kolom itu.
- **Quirk produksi ditiru**: peta venue seni pertunjukan setinggi 0 px di layar < md.
- Paritas `/gci`, `/gpci`, 28 detail, dan 3 halaman pariwisata lulus di 1440 dan 390 (30 Okt 2026).

## Penyimpangan dari teks SPEC (disengaja)

| SPEC | Yang dibuat | Alasan |
|---|---|---|
| §4.4 `Query::build($q, false)` | `Query::build($q)` (encoding RFC 3986) | argumen `false` mematikan percent-encoding: nilai filter berisi `&`, `=`, `#` terpotong. Encoding bawaan tetap menghasilkan `f=` berulang (diuji `DataApiClientTest`) |
| §4.4 "status HTTP diteruskan dari Data API" | 401/403 Data API → **502 `UPSTREAM_AUTH`** | 401/403 dari Data API berarti token layanan Laravel salah (konfigurasi server); meneruskannya membuat Nuxt mengira tokennya sendiri yang salah |
| §5.1 font `@fontsource-variable/plus-jakarta-sans` + `@nuxtjs/fontaine` | berkas woff2 + `@font-face` produksi di-host sendiri | metrik fontsource 5.3.0 berbeda 3,5% dari font produksi (lihat "Font" di atas) |
| §4.4 data di-decode bila perlu dibaca | `data` **diambil mentah** dari body (`JsonMentah::nilaiMentah`), tidak di-decode-encode | decode-encode membulatkan bilangan bulat > 2^63 (UInt64 ClickHouse) menjadi float |
| KONTRAK §2.7 kesehatan | `GET /api/v1/sistem/kesehatan` selalu **200** dengan `status: ok \| terganggu` dan rincian per komponen; `meta.sumber = null` | pemantau tetap bisa membaca komponen mana yang gagal; cek Data API memakai timeout 3 s tanpa retry supaya rute publik ini tidak menahan worker |

## Risiko versi (ditetapkan klien, bukan pilihan kita)

- **Laravel 10**: dukungan keamanan berakhir Februari 2025. `composer audit` (28 Okt 2026) melaporkan
  5 advisory di `laravel/framework` 10.50.4 yang perbaikannya hanya ada di Laravel 12.60+:

  | Advisory | Berlaku di portal? |
  |---|---|
  | CVE-2026-114509 TokenGuard bypass lewat kredensial non-string | tidak: guard `token` tidak dipakai (hanya Sanctum) |
  | CVE-2026-102279 XSS di halaman debug | hanya bila `APP_DEBUG=true` → **wajib `false` di produksi** |
  | PKSA-m5cs-t1y6-qpcs temporary signed URL path confusion | tidak: signed URL tidak dipakai |

  Setiap fitur baru yang memakai komponen di atas (mis. validasi email) harus menilai ulang tabel ini.

## Tafsiran kita atas brief yang belum terkonfirmasi (SPEC §8)

- **"Arsitektur microservice"** ditafsirkan sebagai pemisahan layanan yang hanya saling bicara
  lewat API: Nuxt hanya memanggil Laravel, Laravel hanya memanggil Data API, dan hanya Data API
  yang menyentuh ClickHouse. Di dalam Laravel, tiap fitur adalah modul mandiri
  (`app/Features/<Fitur>`) yang tidak saling memakai — dijaga tes arsitektur. Bila klien
  memaksudkan deployment terpisah per fitur, modul-modul ini bisa dipecah tanpa mengubah kontrak.
- **"Log history di tiap modul"** ditafsirkan sebagai satu tabel `LOG_HISTORY` dengan kolom
  `MODUL` yang diisi otomatis dari atribut rute, ditulis middleware `LogRequest` untuk setiap
  request `/api/v1`. Seluruh perilakunya ada di `app/Shared/LogHistory`, jadi menyesuaikan dengan
  standar knowledge base mereka cukup mengubah satu tempat.
